# バックアップと復旧の手順

2026年8月23日、Manusのプラットフォーム障害（8月25日まで復旧作業中）を受けて整備した。
このドキュメントは **Manusに依存せず** データを守り、必要なら復元するための手順をまとめたもの。

---

## 1. いま何が安全で、何が危険か

| データ | 件数の目安 | リポジトリに複製があるか | 失った場合 |
| --- | --- | --- | --- |
| **動画（videos）** | 180 | ✅ `server/seed/natulaboVideos.ts` | **完全復元できる**。管理画面の「180本をインポート」を押すだけ |
| 会員（users） | 不明 | ❌ なし | **復元不可**。再登録が必要 |
| 招待コード（invitations） | 不明 | ❌ なし | 再発行すればよい |
| イベント（events） | 不明 | ❌ なし | 手入力またはスプレッドシート連携で再投入 |
| 体験談（testimonials） | 不明 | ❌ なし | 投稿者に再依頼 |
| お知らせ（topics） | 不明 | ❌ なし | 作り直し |
| 初期設定ステップ（setup_steps） | 不明 | ❌ なし | 作り直し |
| 問い合わせ窓口（contact_items） | 不明 | ❌ なし | 作り直し |
| 外部リンク（external_links） | 不明 | ❌ なし | 作り直し |
| 視聴進捗（video_views） | 不明 | ❌ なし | 復元不可。会員の学習履歴が消える |
| 閲覧ログ（page_views / login_logs） | 不明 | ❌ なし | 分析用。実害は小さい |
| 画像（managed_images） | 不明 | ❌ なし | 実体はManusストレージ側 |

**最も痛いのは会員データと視聴進捗**。この2つは他のどこにも複製がない。

---

## 2. 復旧したら最初にやること（最優先）

Manusが復旧したら、**他の作業より先に**バックアップを取る。

### 方法A：DATABASE_URL があるとき（推奨・最も完全）

Manusの環境変数設定から `DATABASE_URL` をコピーして、手元で実行する。

```bash
DATABASE_URL='ここに貼り付け' pnpm run db:backup
```

`backups/YYYY-MM-DD_HHmm/` に全テーブルが JSON と CSV で保存される。
`_schema.sql`（CREATE TABLE文）も一緒に出るので、別のDBへそのまま復元できる。

> `backups/` は `.gitignore` 済み。**個人情報を含むのでGitHubにコミットしないこと。**

### 方法B：DATABASE_URL が取れないとき

サイトに管理者としてログインできれば、管理画面経由で吸い出せる。全13テーブルに管理者用の読み取りAPIがあるため、ブラウザ操作で取得可能。Claude Codeに「管理画面からデータを吸い出して」と依頼すれば実施できる。

方法Aより取得できる範囲が狭い（ログ系が一部取れない）が、会員・動画・イベント・体験談などの主要データは揃う。

---

## 3. データが失われていた場合

### すぐ復元できるもの

**動画180本**：管理画面 `/admin/videos` の「180本をインポート」ボタンを押すだけ。
`server/seed/natulaboVideos.ts` に全件のIDとタイトルとカテゴリが入っている。

### 作り直しが必要なもの

- **会員**：招待コードを再発行して、会員に再登録を案内する
- **イベント**：`docs/11_event_sheet_sync.md` の連携を設定すれば、スプレッドシートから一括投入できる
- **その他コンテンツ**：管理画面から手で再登録

### 復元できないもの

- **視聴進捗**：会員がどこまで動画を見たかの記録。再現不可
- **閲覧ログ**：分析用データ

---

## 4. 今後の運用（同じ目に遭わないために）

- **月1回**は `pnpm run db:backup` を手元で実行する
- バックアップは**GitHub以外の場所**（Google Drive、外付けディスクなど）に保管する
- Manusから移行したあとは、ホスティング先の自動バックアップ機能を有効にする

### 自動バックアップの案

GitHub Actions で定期実行し、結果を暗号化して保管する方法もある。ただし `DATABASE_URL` をGitHub Secretsに預けることになるため、移行先が決まってから検討する。

---

## 5. Manus依存からの脱却状況

| 項目 | Manus依存 | 代替の目処 |
| --- | --- | --- |
| セッション管理 | **なし**（自前JWT） | 対応不要 |
| ログインの入口 | あり（Manus OAuth） | Googleログイン直結に差し替え |
| 画像保存 | あり（Forge API） | `@aws-sdk/client-s3` が既に依存にあるため R2/S3 へ移行 |
| ホスティング | あり | Railway / Render |
| 定期実行 | あり（manus-heartbeat） | GitHub Actions |
| データベース | 不明 | `DATABASE_URL` のホスト名で判断 |

詳細な移行手順は、`DATABASE_URL` の所在が判明してから策定する。
